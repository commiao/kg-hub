## 0. 结论

1. **可检索率主要由链路决定，不由模型决定。** 用「只看标题、换说法写的中英文问句」离线评测（MiniLM，top-10 命中本观测的 fact）：
   约定 v1–v2 时三模型中文 22–30%、英文 33–61%；加入「标题结论」「另一语言译文」后升到 76–95% / 95–100%；
   v8 把第一条 fact 改成**照抄标题原文**后，三模型都到 97–100% / 100%，haiku 与 opus/sonnet 的差距消失。
2. **纪律指标三模型全程满分**：2000 条里零边 0、schema 外边名 0、悬空边 0、无类型实体 0、脏命名 2。
3. **模型差异落在三处**：标题改写/翻译的忠实度（haiku 明显弱，v8 后被确定性步骤消除）、误并判读的严谨度（haiku 偏宽）、成本（sonnet 最省）。
4. **与 10-17 上次相比**：可检索率从 15–28% 提到 97–100%，密度从 4.0–5.6 实体 / 2.8–4.3 边 提到约 5.7–6.0 / 4.3–4.7，dry-run 拦下真误并后残留误并率约 0.01–0.03 / 条（上次 0.15–0.76 / 条的误并候选，未逐条判读）。
5. **对 deepseek 的含义**：差距主要在链路（deepseek sp2 同口径 45% / 69%），把 v8 的结论移植到单次抽取（PR #208，sp3：标题原文边由服务端确定性补齐），预计 deepseek 也能到同档，且成本只有 1 次调用 / 条。

## 1. 实验设置

- 样本：refinery 积压中 obs 28131–37375 的 2000 条，切成 40 批 × 50（b0001–b0005 中文为主，b0006 起英文为主）；第 40 批拆成 17/17/16 三份，三模型各 666–667 条。
- 编排：每轮三模型各拿一批相邻时段的观测（顺序轮换），轮后复盘、改约定，**约定改动对三模型同时生效**；共 14 轮、8 版约定（chain-v1…v8）。
- 第 5 轮起抽取与提交解耦：子代理先只抽取，提交由编排者逐个放行（NAS 同时只有一个提交；NAS 平均温度 > 90°C 时暂停 4–5 分钟）。
- 服务端：线上 kg-hub-server 7a32693（单次抽取 + MiniLM + 仓库前缀守卫 #205 + 向量索引 #206）；对立词守卫 #207 已合并未发布。

读法：v1–v2 → v3 主要抬英文（标题多为英文），v5 抬中文（中文提问有了同语言入口），v8 抹平模型差距。
v3/v4 中文差异与批次语言有关（b0001–b0005 中文标题、之后英文标题）；同轮内三模型对比可靠，跨轮只看方向。
**口径偏置**：问句由标题改写，照抄标题的 fact 天然最近；但它对三模型一视同仁，「模型差距被抹平」的结论成立。

### 2.3 haiku 在 v7 时为什么低 15–25 个点

第一条 fact（标题结论）与标题的语义相似度：opus/sonnet 0.91–0.99，haiku 0.79–0.86（20% 低于 0.7）；第二条译文 haiku 0.66–0.71，另两模型 0.75–0.82。
haiku 规则执行率 100%，但改写与翻译时偏离原意——这是模型能力差，v8 用照抄把这一步变成确定性的。

- **建议步骤**（都需用户拍板）：① 合并 #208 并与 #207 一起发布（NAS 降到 80°C 以下的窗口）；② 恢复断路器跑 50 条金丝雀，按上面口径复测；③ 关注 deepseek 的译文质量（第二条边）——这是唯一仍依赖模型能力的入口；④ 达标（中文 ≥ 90%、英文 ≥ 95%、零边 ≤ 2%、误并候选可控）再常态恢复，恢复前知会 T-0219。
