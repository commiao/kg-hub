## 0. 结论

1. **Claude 会话自抽取在「纪律」上全面优于网关旧模型**：三个模型边名合规率都是 100%（存量 31–60%）、无类型实体 0（存量 7–17%）、
   重复三元组 0（存量 3–7%）、自创边名 8–13 种（存量每月 1.2k–15.7k 种）。这是 schema 可检索性的决定因素，旧存量里 1.57 万种
   自创边名让 `kg_search` 的边检索基本失效。
2. **但 Claude 抽得稀**：fable 每条 5.6 实体 / 4.3 边、摘要 166 字，deepseek 存量是 12.4 / 12.7 / 398 字。密度差距一部分是规则
   有意为之（回顾/复述类观测只抽新增事实、授权类给空，第 3 轮 23% 的观测属此类），一部分是模型保守。存量的高密度里相当一部分
   是噪声（自创边名、重复三元组、commit 哈希与绝对路径当实体）。
3. **三轮里 fable 这一轮入图质量最好**（边/条 4.27、误并率 0.15、入库误并 1 对），**但可单独归因于模型的只有关系密度与复述判别**；
   误并从 0.76 → 0.35 → 0.15 主要来自服务端消解收紧、类型守卫、dry-run 预览这三项与模型无关的改动。
4. **最划算的方式不是继续换模型**：用同一套 v3 工具链（消解收紧 + 类型守卫 + dry-run + 前瞻 + 已用名）跑 opus，第 2 轮 17 对误并里
   15 对会在新消解下直接消失，成本低于 fable；haiku 的关系稀疏（22% 观测不足 3 边）和类型错配是模型侧问题，不建议做主力。
   比换模型更省的是源头：第 3 轮 23% 是同一会话对同一文件的再读/复述观测，在 claude-mem 侧或取批阶段折叠能省更多。
5. 实际消化：三轮共入库 1,528 条（haiku 500、opus 517、fable 511）+ 33 条判空；live 待处理从 14,106 降到约 12,500。

## 2. 每轮复盘与实践过的优化

### 第 1 轮 · claude-haiku-5-5 · 500 条（b0002–b0026）· 规则 agent-v1

- 结果：500/500 ok；图口径边名合规 100%、边名 10 种、重复 0、零边 0、摘要均长 33.6 字。
- 最差三类：实体误并（跨类型：Issue 并进 Config、Tool 并进 Issue；同名不同路径文件互并）；关系覆盖不足（22% 观测不足 3 边，
  把「3–10」当成了上限）；被后续观测推翻的判断与同一对象的矛盾状态原样入库。
- **教训 → 第 2 轮调参**（检查点登记）：`prompt_version` v1→v2（关系下限 3、可区分命名、被推翻判断不入库、读全文、自检悬空边）；
  `type_guard_on_resolution`=true（服务端，向量候选必须带抽出的类型标签）；`batch_size`=20 不变。
- 顺带修掉的工具问题：复盘工具跨事件循环关驱动（checkpoint 连续失败、gate 偶发 rc=1）；边数查询扫全边超时；retro 参数透传；
  执行器按 refinery 水位选观测（首次冒烟取到了 6 月存量）。

### 第 2 轮 · claude-opus-5-5 · 540 条（b0027–b0053）· 规则 agent-v2 + 类型守卫

- 结果：517 ok / 23 empty；图口径边名合规 100%、13 种、重复 0、摘要均长 75 字。
- **改善证据**：关系不足 3 条的观测 109/500 → 0/517（规则 9）；纯授权/回顾观测给空 0 → 23（规则 9）；跨类型误并 0 例
  （类型守卫，可单独归因）；reuse_mismatch 每条 0.76 → 0.35；同批内被推翻的判断只抽结论（规则 11）。
- 最差三类：同类型近名误并 17 对（兄弟概念共享长前缀、只差一个字符/数字/日期、跨仓库同名文件、描述性名字被泛名吸进；
  首次并错后同名持续命中错误节点）；跨批被推翻的判断 5 组（流式取批看不到后面的更正）；回顾/复述类观测被硬凑出近义节点。
- **教训 → 第 3 轮调参**（`digest_retro tune` 登记）：`resolution_strictness`=v3（服务端：代码类名字与 File/Config 只认完全相等，
  例外为全路径与子路径；只在数字上不同的不复用；包含占比 0.5→0.8；difflib 0.72→0.85）；`submit_dry_run`=true（接口 `dry_run`
  只消解不写图，执行者写入前预览并改名）；`prompt_version` v2→v3（区分词放最前、只差动词的标识符取一个、跨仓库文件写 `仓库:路径`、
  事件带描述、回顾/复述类观测给空或只抽新增、用前瞻与 dry-run、复用已用名）；执行器加 `lookahead` 与 `names-<model>.tsv`。

### 第 3 轮 · claude-fable-5-1 · 520 条（b0054–b0079）· 规则 agent-v3 + 消解收紧 + dry-run

- 结果：511 ok / 9 empty；图口径边名合规 100%、13 种、重复 0、零边 0.2%、摘要均长 166 字；中途撞一次周限额，从 b0059 断点续跑。
- **改善证据**：reuse_mismatch 每条 0.35 → 0.15；入库误并 17 对 → 1 对；只差数字/日期的误并 0、跨仓库同名 File 入库误并 0
  （3 次被 dry-run 拦下）——这两项对应服务端收紧与 dry-run，可单独归因；由执行者起名造成的同前缀误并 0；前瞻窗口内约 25 组
  推翻全部只抽结论；复述类 116 条只给 0–2 边（规则 18），empty 23 → 9。
- 最差三类：规则 16 的 `仓库:路径` 被服务端 `:` 后缀例外吞掉（已修，见第 3 节）；超出前瞻窗口的改写 4 组只能叠加 supersedes 边；
  同一 diff 的几十条再读观测把增量压进同几个核心节点，仍新建了价值有限的节点；dry-run 与正式提交对同一输入结果不一致 1 次
  （候选排序不确定，已修）；本地自检拦下悬空边约 45 处。
- 对「最优方式」的判断见第 0 节第 3–4 条。
