# T-0033 transport and alert hardening — 2026-09-08

The sync launcher now owns a 600-second deadline independently of launchd. Both
Mac sync and NAS apply use kernel file locks. NAS apply has its own 300-second
limit, so an orphaned remote command cannot block subsequent writers indefinitely.
The supervisor terminates the whole child process group and returns 124 on timeout;
a concurrent invocation returns 75 before entering the shared-file cleanup path.
Lock files are deliberately never unlinked. The descriptor is inherited by writers.

Script auto-update validates SHA-256 before installation, including the new remote
supervisor. The data path remains SQLite deltas via Drive, with SSH fallback and
validated atomic replacement for full recovery.

Watchdog persists pending deliveries before sending, checks Feishu business codes,
and retries failed deliveries on subsequent monitoring cycles. Node identities
trigger notifications for new blockers even while another capture blocker remains
active. Changing ages and row counts do not retrigger alerts. Recovery supersedes
an obsolete pending failure notification. A crash after server acknowledgement but
before local persistence can still cause a duplicate notification (at-least-once).
