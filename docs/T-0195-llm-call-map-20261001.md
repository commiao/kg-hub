# T-0195：LLM 调用在做什么、关闭思考的对比

## 口径与当前设置

2026-10-01 19:50 左右（北京时间）直接读取 NAS model-gateway 运行配置：
`kg_hub.entity_extract` → `qwen3.8-flash`，`thinking_policy=disabled`，
`max_tokens=8192`，`timeout=150s`。这里 entity_extract 是整条 Graphiti 链共用的
业务路由名，不代表该路由上的每次请求都在抽实体。网关覆盖客户端输出上限；
探针请求体中的 4096 不是已证实的上游生效上限。

此前所有 SP/温度/修改列表试验也请求关闭思考，没有开启思考的质量或耗时样本。
因此目前能够比较的是“关闭思考下不同方案”，不能比较开/关思考的因果效果。
用户本轮第 1 项暂按保持关闭思考理解，已请求澄清；未改动生产思考权限。

### 容易混淆的地方

- 属性的 `description` 和实体 `summary` 是不同字段、不同调用。
- 向量生成（embedding）、向量/全文检索、预校验、写锁、提交都不在这张生成型 LLM 调用表中。
- 关系属性抽取在有非空关系 schema 时也可能调用；当前关系模型多为空，本窗口未独立识别到该类调用。
- 逐条去重/时间调用不一定都是失败重试：单个任务也可能直接走逐条路径。
- 图状态冲突会让部分业务阶段重新执行；相同身份的已完成请求重放不等于一次新付费调用。
- 社区聚合等 Graphiti 可选功能不等于本次普通入图的必经阶段，没有计入常规链路。

## 对吞吐目标的实际意义

当前属性相关请求约占观察调用的 29%。即使这一类请求数全部减半，整条链路也
只减少约 14% 请求；8→16 对小样本甚至不会减少调用。不能把属性阶段的 2→1
描述成整条入图链吞吐翻倍。真正的业务验收仍需成功入图/小时、积压净减少、
每条成功入图的调用成本、错误率与质量同时改善。

优先级：

1. 先验证属性合并是否保住事实和旧值；目前难例未通过，不能上线。
2. 依据跨样本错误定位任务复杂度和实体类型的影响，决定是否需要缩小合并范围。
3. 单独评估实体抽取与关系抽取是否可联合（本窗口合计104次），保持后续实体/关系消解的图候选依赖。
4. 关系去重已合批，进一步扩大批次需要重新验证重复与矛盾判断，不能仅按调用数放行。
5. 时间抽取约4%，不是当前优先投入项。摘要已有无模型快捷路径，不能假设41次都可删除。

## 关闭思考的六样本配对筛选（运行前协议）

冻结此前未调词的六个样本，使用既有源文验收表（见主证据文档）逐条人工复核。
最多18次新调用，不写图。原方案每样本8+8两次；候选每样本16一次，使用已冻结的
完整原文引用 SP、温度0、移除 previous_episodes。原方案保留生产温度1和原上下文。
这是两个完整方案的比较，**不是**单独改变思考、温度或批次的因果实验。

两组共用当前原文、原属性、实体身份和模型路由。原方案/候选先后顺序逐样本交替，
记录前缀缓存状态；无法消除上游负载变化，单轮耗时不当作可靠尾延迟。原方案结果
也需要源文验收，不把它视为金标。开发难例先前的失败不因跨样本通过而消失。
schema 失败保留原始 payload；未知网络/付费结果立即停止，不换请求键自动重试。

本轮新增 `--paired-screen` 和顺序切换参数；30项工具测试通过。

保持关闭思考、一次最多16实体、完整属性返回。没有采用上一轮失败的修改列表
契约。仅在隔离探针增加：

1. 原文按名称提取普通字段候选证据，提供完整文件路径/Project行；程序不预填答案。
2. 明确 File.path、Config.path/content_hash、Tool.category/version 等字段含义。

3. 每个实体内部的 JSON schema 也设 extra=forbid，不再只约束最外层实体键。
4. 保留已有事实，同时用不涉及业务样本的例子明确“已解决疑问需要更新旧待查表述”。
5. 补充当前 episode.valid_at，禁止把入库时间/其他历史观测日期当成事件时间。

第5项有代码和输入证据：Graphiti `_build_episode_context` 对单个episode只传
content，却传了历史episode的timestamp；f795样本 valid_at 为

原方案输出“2026-10-01验证”是不正确的事件日期，不属于文字风格差异。

### 可验证假设与变更

旧候选同时携带重复旧值模板、保留指令、原文引用与末尾复核，容易让复制旧值
压过纠正旧主张。统一契约 v1 将其替换为单一 SP，把名称匹配证据放进用户数据；
明确历史需求、实际实现和建议不同，普通字段不能追加说明。沿用严格 schema，
保留原文/旧属性，未作输出补值或语义修复。

v1 输出显示新的缺省字段问题：输入旧属性缺失的未知键，模型也在输出中省略。
v2 恢复完整字段模板，只预填普通字段的原值；description 使用占位符避免重复
旧描述，并要求完整源文条件和保留历史需求。v3 在 v2 基础上只把**输入**旧属性
中缺省的 schema 字段补成 null，验证稀疏输入是否导致缺键；已有值均保持不变，
模型输出缺键仍判失败，不作补救。

做预声明的独立重复与新留出样本验收。未知付费结果停止，不更换键重试。

需要独立实验路由及受保护的思考权限授权。当前生产路由强制 disabled；仅在
请求里写 enabled 会被网关覆盖。源码还检查 thinking_policy_permission，
不会绕过此限制或改生产实体抽取路由。开启思考可能增加输出成本和延迟，
不能预先宣称净收益。替代方向是保持思考关闭、先审查哪些约束可由程序安全
验证或限定候选值，再决定是否值得新增模型调用；不得自动修补语义答案。

## 代码定位

- `graphiti_client.py`：安装属性/去重/时间合批补丁和统一模型客户端。
- `utils/batched_node_attributes.py`：8实体属性合批、残缺答案捞回、单实体回退。
- `utils/batched_edge_dedupe.py`：关系重复/矛盾判断合批，默认上限12。
- `utils/batched_edge_timestamps.py`：时间抽取合批，默认上限12。
- 运行环境 Graphiti `utils/maintenance/node_operations.py`：实体抽取/消解、属性和摘要。
- 运行环境 Graphiti `utils/maintenance/edge_operations.py`：关系抽取、时间、去重与可选关系属性。
- `utils/model_attempt_journal.py`：本地持久化模型调用状态与回执。
- `tools/attribute_prompt_probe.py`：隔离质量/耗时试验，不修改生产流水线。
